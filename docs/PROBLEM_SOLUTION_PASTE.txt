## Problem

Traditional e-commerce search is mostly one-shot keyword matching. Shoppers don't talk that way: they browse, change their mind, add constraints over several turns, and still expect the right product quickly.

On large catalogs (here: frozen Amazon Clothing, Shoes & Jewelry, 50k items), that fails when:

- Queries are vague ("something nice for summer")
- Language is ambiguous ("dress" vs dress shoes; "for my son" vs women's items)
- Preferences change mid-chat (intent override)
- The system re-asks slots already answered or burns the 10-turn budget

The TechJam track asks for a multi-turn shopping agent that recovers a hidden target parent_asin under buying / browsing / override / boundary scenarios, scored by:

- Hit@10 — is the purchase in the top 10?
- MRR — how high is it ranked?
- MTTC — how many turns until first hit?

…combined into TechnicalScore, with a hard ≤10 turns cap (misses hurt badly).

Real-world stakes match the kit: weak search UX drives refine-loops and abandonment; conversational commerce only works if the catalog brain can clarify, remember state, and rank exactly — not just chat.

## Solution

ShopPilot is a headless, **offline-first** multi-turn shopping agent (demo UI: Astrid CLI). Same API every turn: natural message + one structured ask_attribute + ranked recommendations.

**No external API is required** for scoring or the default demo. Optional cloud LLMs are fail-open and off by default. MiniLM dense, when enabled, is a **local** sentence encoder (on-device embeddings), not a hosted chat API.

### How it works

1. Intent & routing
   - Buying vs browsing cues
   - Internal product family (e.g. garment dress ≠ dress sandals)
   - Internal audience (e.g. "for my son" → demote women's items)

2. Dialog state
   - Slots aligned to the official enum: color, material, size, style, brand, budget, feature, use_case, category, other
   - Soft / disclosed / override sources; soft-only wipe on mind-change (keep hard disclosed facts)
   - Skip filled / dont_care; no dumb re-asks
   - Rich freeform lines fill multiple slots in one turn

3. Clarify when vague
   - Same turn: recommendations and a question
   - First ask = other (protocol catch-all); optional second other while thin
   - Then static ladder; max-IG ask order measured and rejected

4. Hybrid retrieve + rank (all local)
   - In-memory SQLite FTS5 + optional dense hash or local MiniLM
   - Evidence coverage×exact, category-tail, family/audience, margin-gated Top-K emission
   - First hit freezes MRR — uncertain turns emit Top-1

### Results (public 200, official local evaluator)

| Backend | Tech | Hit@10 | MRR | MTTC | Tokens |
|---|---:|---:|---:|---:|---:|
| Weak BM25 starter | ~0.11 | 0.125 | ~0.07 | ~9.8 | 0 |
| ShopPilot hash (default ship) | **~0.909** | **0.975** | **~0.872** | **~3.01** | **0** |
| ShopPilot MiniLM (local opt-in) | **~0.910** | **0.980** | ~0.867 | ~2.98 | **0 API** |

Judges can disable network: default path still runs. Cloud LLM is never required.

### Offline claim

ShopPilot's default and reported scoring path is fully offline—no external API. Dense MiniLM, when enabled, runs as a local encoder; any cloud LLM is optional, default-off, and unused for the hash ship metrics (Tech ~0.909, 0 tokens).
