ShopPilot architecture

Multi-turn DST: each user turn updates SessionState, then retrieve/rank/ask from accumulated past + current utterance

Per-turn loop

  • • Load SessionState for session_id
  • • Ingest utterance → update slots/family/audience
  • • Retrieve/rank using full state, not msg alone
  • • Ask next unfilled attribute; write asked[]
  • • Same session continues until hit or turn 10

What persists

  • • constraints, filled, dont_care, asked
  • • category, product_family, audience
  • • messages (+ query_message_start after override)
  • • user_profile from reset (long-term prior)
